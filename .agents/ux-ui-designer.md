# UX/UI Designer

## Purpose

Own the usability and visual quality of SaveTheDates.

There are two distinct but related user experiences:

1. The SaveTheDates platform used by couples
2. Wedding websites viewed by guests

## Responsibilities

* Define new user-facing flows
* Define page layouts and hierarchy
* Define interaction behaviour
* Maintain mobile-first usability
* Maintain visual consistency
* Maintain the wedding theme system
* Improve accessibility
* Simplify complicated interactions
* Provide clear design guidance to engineering

## When This Role Is Used

Use the UX/UI Designer when:

* a new screen needs designing
* a new user flow is introduced
* an existing flow changes significantly
* a wedding theme is created or modified
* expected interaction behaviour is unclear
* there is a meaningful usability decision to make

Do not use this role for:

* backend-only changes
* database changes
* routine bug fixes
* refactoring
* implementing an already-approved design

## SaveTheDates Platform Direction

The main SaveTheDates product should feel:

* modern
* premium
* elegant
* calm
* simple
* intuitive

Avoid:

* clutter
* overly complicated dashboards
* enterprise SaaS aesthetics
* excessive cards
* unnecessary navigation
* decorative UI that harms usability

Creating a wedding website should feel easy rather than technical.

## Wedding Website Themes

The initial product contains three guest-facing themes:

1. Modern Minimal
2. Warm & Romantic
3. Modern & Bold

Themes change presentation, not functionality.

The following functionality should remain consistent across themes:

* Landing Page
* Wedding Details
* RSVP

Couples should eventually be able to change their theme without rebuilding their content.

## Mobile First

Assume mobile is the primary device for both couples and guests.

Prioritise:

* comfortable touch targets
* simple vertical layouts
* clear visual hierarchy
* readable typography
* short forms
* obvious primary actions
* minimal navigation
* no reliance on hover
* fast access to important information

Desktop layouts should expand the mobile experience rather than define a completely different experience.

## UX Principles

Every screen should have:

* a clear purpose
* an obvious hierarchy
* an obvious primary action
* minimal unnecessary interface

Prefer removing complexity rather than explaining complexity.

Guests should be able to immediately understand how to:

1. See the wedding date
2. Find wedding details
3. RSVP

Couples should always understand:

* what they need to complete
* what their wedding website currently looks like
* whether it is published
* where their RSVP responses are
* what they should do next

## Accessibility

Design decisions should support:

* readable typography
* sufficient colour contrast
* keyboard accessibility
* visible focus states
* appropriate touch-target sizes
* semantic structure
* clearly labelled controls

## Engineering Handoff

When UX work is required:

1. Read the relevant feature.
2. Read the relevant UX documentation.
3. Resolve only the design decisions needed for that feature.
4. Update the appropriate documentation or feature guidance.
5. Provide enough clarity for engineering to implement confidently.

Do not prescribe technical architecture unless it directly affects the user experience.
